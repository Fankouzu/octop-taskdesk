# 架构

## 分层

```
L3  台账层     飞书多维表格（数据在外，人在表里看进度）
L2  插件/MCP层  自定义 MCP、hook、skill
L1  配置层     agent 定义、system_prompt、渠道绑定
L0  Octop 内核  octop_harness / octop_gateway（site-packages，不修改）
```

原则：**不动 L0**。内核是 pip 包，改了下一次升级就丢；所有定制都在 L1/L2。

Octop 主包是 editable 安装（`.pth` 指向 `/app/src`），`/data/.octop/` 是 bind mount，
容器升级不丢数据。所以**代码和配置都放 `/data` 下，不放镜像里**。

## 三个角色

| 角色 | kind | 职责 | 能碰什么 |
|---|---|---|---|
| 任务台 | team | 判断、分派、自检、回复 | 只能 `ask_agent`，不能写表 |
| 台账员 | expert | 唯一写台账 | shell 调 `ledger.py` |
| 业务专家 | expert | 干活 | 按需给 MCP / 技能 |

### 为什么任务台是 team

Octop 对 `kind=team` 的 host 会调用 `_apply_team_host_config()` 强制裁剪：
只保留 `agent_list` / `ask_agent` / `memory_search` / `memory_get` / `current_time`，
MCP 连接器清空、技能目录置空。

这个约束看似限制，实际上正好：任务台的职责就是"不干活"。
它越没有工具，越不会自己去写文档、查资料、绕过分派。

### 为什么台账员不挂 MCP

Feishu 连接器的 `base` 工具在模型手里不可靠，实测三种失败：

1. 把 `args` 传成 JSON 字符串而不是对象
2. 不确定参数时用 `+title-resolve` 之类的错误子命令反复试探
3. 把权限问题误判成"需要用户去后台授权"

改成**固定脚本 + 固定参数**后一次通过。脚本自己处理了矩阵格式解析、
`record_id` 的嵌套位置、枚举值校验。

## 数据流

```
用户 → 飞书 → 任务台
                ├─ 判断要不要建单（三条全满足才建）
                ├─ ask_agent 台账员 → add-demand / add-task
                ├─ ask_agent 专家 → 产出交付物
                ├─ 自检（事实有出处、格式合规、覆盖要求），不合格打回，最多 2 轮
                ├─ ask_agent 台账员 → task-status / demand-status
                └─ 回复用户（≤100 字，只讲结论和位置）
```

## 写入口唯一

所有对表格的写入只走 `ledger/ledger.py` 的六条命令。
不开放"任意 JSON 直接 upsert"的入口，原因：

- 模型会写出枚举外的状态值，静默失败
- 字段类型猜错（单选题要数组、文本要字符串）
- 建单前不查重，重复建单

脚本内置了查重、枚举校验、状态联动（子任务全完成才关闭需求）。

## 扩展点

| 想加什么 | 加在哪 | 注意 |
|---|---|---|
| 新的专家 | 新建 expert agent | 不要给任务台加工具 |
| 巡检/告警 | cron_jobs + 独立 watchdog agent | 只在"需要人决策"时推消息，否则变成催办噪音 |
| 准入控制 | hook（langchain `AgentMiddleware`） | 插件 kind 有 `tool`/`skill`/`hook`/`channel` |
| 自定义 MCP | `mcp_servers` 配置 | 支持 `stdio` 和 `streamable_http`；`ssrf_guard` 拒绝内网地址和 http |

## 表结构

`schema/base_schema.json` 是脱敏后的完整结构：13 表 190 字段。
表 ID 和字段 ID 都被替换成 `t01` / `t01f001` 这类别名，
建表脚本靠这个别名做 src→dst 映射，换模板时重新导出一份即可。

核心两张表：

- **需求表**：一件事一行。主字段"需求名称"，状态 `待评审/已确认/开发中/已完成`
- **开发任务表**：一条需求拆多行。主字段"任务名称"，
  状态 `未开始/开发中/待验收/已驳回/已完成`，`驳回轮次` 超过 2 转人工

主字段必须选**语义上是名字**的那个文本字段。按"第一个文本字段"取会踩坑——
曾经把"项目描述"当成了主字段。

## 身份

两种身份，不能混：

- `--as bot`：应用身份。用于写入、建表。应用自建的表会成为 full_access 所有者。
- `--as user`：用户身份。用于导出模板结构这类需要读别人表格的场景。

应用没有 base 权限时会报 `99991672`。解法不是找用户去后台加权限，
而是**让应用自己建一张表**——应用自动成为所有者，并自动把创建者加为协作者，
绕开"分享面板里选不到智能体"的产品限制。
